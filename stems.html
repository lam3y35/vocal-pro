Understanding Stems in VocalPro

A complete guide to audio source separation, the Demucs AI models, the stem mixer, MIDI extraction, karaoke mode, SFX separation, and every setting that controls how VocalPro breaks apart and reassembles your music.

Fundamentals

What Are Stems?

In audio production, a stem is an isolated audio track containing a single category of sound extracted from a full mixed recording. For example, a song's final mix can be separated into vocals, drums, bass, and other (all remaining instruments) — each saved as its own independent audio file.

🥁 Drums Percussion
🎸 Bass Bass guitar
🎹 Other Instruments
🎹 Piano 6-stem only
🎸 Guitar 6-stem only

Stem separation has many practical uses. Musicians extract vocals for remixes or acapellas. Content creators isolate dialogue from background music. DJs grab drum tracks for beatmatching. Producers analyze individual instrument parts for transcription or study. The Demucs AI models powering VocalPro make this possible with studio-quality results — entirely offline on your own machine.

🎯 Key Concept

A typical mixed song is a single audio file where all instruments and vocals are summed together. Stem separation is the process of inverting this mix — recovering the individual source tracks from the combined signal. Demucs achieves this by learning the unique spectral, temporal, and harmonic patterns of each instrument type through deep learning on thousands of multitrack recordings.

Stem Descriptions

🎤

Vocals

The lead vocal track. This is the primary output — VocalPro applies extensive post-processing (gating, denoising, multi-band filtering) to deliver the cleanest possible voice isolation. Optionally mixed with separated sound effects.

🥁

Drums

All percussive elements — kick drum, snare, hi-hats, cymbals, toms, and any other percussion. Demucs isolates these using the model's learned understanding of transient-heavy sounds.

🎸

Bass

The bass guitar or synth bass line. Contains low-frequency harmonic content that Demucs separates by recognizing consistent sub-bass patterns distinct from kick drum transients.

🎛️

Other

Everything else — guitars, keyboards, strings, brass, synths, pads, and any instrument not classified as vocals, drums, or bass. This is the most diverse stem and is further post-processed for SFX separation if enabled.

🎹

Piano (6-stem only)

Isolated piano track — only available with the htdemucs_6s model. The model has a dedicated output head trained specifically to recognize piano timbre across the full frequency range.

🎸

Guitar (6-stem only)

Isolated guitar track — only available with the htdemucs_6s model. Covers both acoustic and electric guitars, recognized by their characteristic harmonic structure and transient decay.

Pipeline

How Stem Separation Works

The separation pipeline is a multi-stage process that converts a mixed audio file into individual stem tracks. Here's exactly what happens under the hood.

📂 Load Audio → 🧠 Demucs Model → 🎛️ Split into Stems → 🔊 Post-Process → 🎚️ Stem Mixer → 💾 Export
1

Load & Prepare Audio

The input file (audio or video) is loaded using soundfile or FFmpeg. For video files, the audio stream is extracted as a high-quality WAV. The audio is resampled to the model's native sample rate (44.1 kHz) using torchaudio resampling with GPU acceleration. The resulting waveform tensor is shaped as (1, channels, samples) for the model.

2

AI Model Inference (Demucs)

The core separation is performed by Demucs — a Hybrid Transformer architecture that combines convolutional U-Net layers with transformer self-attention. The model processes the audio through:

  • Segmentation — The audio is split into overlapping segments (default 24 seconds, configurable). Each segment is processed independently.
  • Shift Averaging — Each segment is shifted by random offsets (shifts parameter, default 5). The model processes each shift, then the results are averaged. This reduces boundary artifacts and improves separation quality by 1-3 dB SDR.
  • Overlap-Add — Segments are reassembled with raised-cosine crossfade (25% overlap) to eliminate click artifacts at segment boundaries.
  • Normalization — The model applies internal gain staging to maintain consistent levels regardless of input loudness.
3

Source Separation & Stem Output

The model outputs a tensor of shape (1, sources, channels, samples) where sources corresponds to each stem type (4 for standard models, 6 for htdemucs_6s). Each source is extracted as a separate NumPy array via stems[0, i, :, :total_frames].cpu().numpy(). These arrays are returned as a dictionary keyed by source name: {'vocals': ..., 'drums': ..., 'bass': ..., 'other': ...}.

The model's sources attribute determines which stems are produced. Standard Demucs sources: ['vocals', 'drums', 'bass', 'other']. The htdemucs_6s model adds 'piano' and 'guitar'.

4

Post-Processing Pipeline

The raw separated stems go through an intensive refinement pipeline. The vocals stem receives the most processing:

  • Vocal Activity Detection (VAD) — Analyzes RMS energy, spectral flatness, and spectral centroid to identify vocal vs. silent regions.
  • Spectral Noise Reduction — noisereduce spectral gating with non-stationary mode removes residual music bleed from vocal sections.
  • Multi-Band Denoising — Applies different denoising strengths to low (rumble), mid (vocal range), and high (hiss) frequency bands independently using zero-phase Butterworth filters.
  • Adaptive Gate Floor — Dynamically measures the actual noise floor from VAD-identified silent sections and adjusts the gate threshold accordingly.
  • Vocal Gating — Silences instrumental-only sections while preserving natural vocal attack/decay with smooth raised-cosine fades.
  • HPSS SFX Separation — Optionally decomposes the "other" stem into harmonic (sustained music) and percussive (sound effects, impacts, transients) components using librosa HPSS.
  • Karaoke Mode — Sums all non-vocal stems (drums, bass, other, piano, guitar) into a single instrumental karaoke track saved alongside the vocals.
  • Ensemble Mode — Runs audio through both htdemucs_ft and mdx_extra models and averages their vocal outputs for cleaner results.
5

Stem Mixer & Export

After separation, all stems are available in the output folder. The Stem Mixer UI panel gives you individual volume sliders (0–200%) for each stem. You can:

  • Mix & Export — Blend all stems at custom levels into a single WAV/MP3/FLAC file
  • Export All (Custom) — Save each stem at its slider level as a separate file
  • Export All Stems — Save every stem at full volume (0 dB) as separate files
  • MIDI Extraction — Extract pitch contours from any melodic stem using librosa.pyin and save as a standard MIDI file
  • MIDI All — Batch MIDI extraction from all melodic stems at once

🎚️ Per-Stem Volume Sliders

Each stem gets its own slider ranging from 0% (muted) to 200% (+6 dB gain). Drag to remix the balance. The slider positions are displayed as percentage values next to each control.

🎧 Mix & Export

Blends all stems at their current slider levels into a single audio file named stem_mix.wav (or .mp3/.flac). The API endpoint POST /api/stems/export reads each stem file, applies the volume gain, sums them together, and writes the result with a master volume multiplier.

📦 Export All (Custom)

Exports every stem as a separate WAV file, each at its individual slider level. Result files are named {stem}_custom.wav. Uses the API endpoint POST /api/stems/export_separate.

📤 Export All Stems

Saves every stem at full 0 dB volume (no slider adjustment) as separate files. Useful when you just want all the raw stems without any custom mixing.

🎵 MIDI Extraction (Per-Stem)

Click the 🎵 MIDI button next to any melodic stem to extract its pitch contour. Uses librosa.pyin (probabilistic YIN algorithm) with frequency range C2–C7. Detected pitches are quantized to MIDI notes, written as a standard .mid file. Also saves a debug WAV of the detected pitches.

🎵 MIDI All

Batch MIDI extraction from all melodic stems (vocals, piano, guitar, bass) at once, saving individual .mid files for each. Uses the same librosa.pyin algorithm as single-stem extraction.

🔧 How Mixing Works Under the Hood

When you adjust a slider and export, the Flutter frontend sends a request to POST /api/stems/export with the folder name, per-stem volume map (e.g. {'vocals': 0.8, 'drums': 0.5, 'bass': 1.2, 'other': 0.7}), and a master volume. The API reads each stem WAV file with soundfile, applies the gain factor, sums them together sample-by-sample, and writes the mixed result. The preview endpoint (/api/stems/preview) does the same but only processes the first 15 seconds and returns an in-memory WAV stream for quick auditioning.

Refinement

Post-Processing: From Raw Stems to Polished Audio

Raw separated stems from Demucs can have residual bleed from other instruments. VocalPro's post-processing pipeline cleans this up with surgical precision.

🎤 VAD Detection → 🔇 Vocal Gating → 🔊 Spectral Denoise → 🎛️ Multi-Band Denoise → 📊 Adaptive Floor → 🔬 HPSS SFX Sep.

🎤 Vocal Activity Detection (VAD)

Combines three features for robust detection: RMS energy (loudness), spectral flatness (tonality vs. noise), and spectral centroid (brightness). Frames are classified as vocal if at least 2 of the 3 features exceed adaptive thresholds. A minimum vocal duration filter (default 0.05s) prevents short noise bursts from triggering false positives, and a margin of 4 frames pads vocal regions to avoid cutting off natural attack/decay.

🔇 Vocal Gating

Uses the VAD envelope to apply smooth gain: vocal regions pass through at unity gain, while non-vocal regions are attenuated to the gate floor (default −60 dB). Attack/release times (10 ms / 100 ms) prevent clicks. The gate floor can be set adaptively based on measured noise from silent sections.

🔊 Spectral Denoising

Applies noisereduce spectral gating with non-stationary noise mode (adaptive to varying music backgrounds). If noise profiling is enabled, a noise sample is extracted from VAD-identified silent sections for targeted removal. Strength parameter (0–1) controls how aggressive the reduction is.

🎛️ Multi-Band Denoising

Splits the signal into three bands using zero-phase Butterworth filters: low (rumble, <250 Hz), mid (vocal range, 250–6000 Hz), and high (hiss, >6000 Hz). Each band gets its own denoising strength — mid band is treated gently (default 0.30) to preserve voice quality, while low (0.65) and high (0.60) bands are denoised more aggressively. The bands are summed back exactly: L + M + H = original signal.

📊 Adaptive Gate Floor

Instead of a fixed silence threshold, VocalPro measures the actual noise floor from the quietest 10th percentile of VAD-silent frames. The gate floor is set to this measured noise floor + 3 dB headroom, ensuring optimal silence without cutting into quiet vocal passages.

🔬 HPSS SFX Separation

Uses Harmonic-Percussive Source Separation from librosa to decompose the "other" (background music) stem into two components: harmonic (sustained musical tones — the music track) and percussive (transients, impacts, clicks — the sound effects). Uses asymmetric margins (harmonic: 3 dB, percussive: 1 dB) with a small kernel size (15 samples) to favor SFX preservation. No separate model required — mathematically exact.

🎤 Karaoke Mode

When enabled, all non-vocal stems (drums, bass, other, piano, guitar) are summed together into a single instrumental track and saved as {filename}_karaoke.wav. The vocals are saved separately as usual. The mix is computed by summing the NumPy arrays element-wise — stems are zero-padded to match the longest duration.

🔀 Ensemble Mode

Runs audio through two different models — htdemucs_ft and mdx_extra — then averages their vocal outputs. This combines the strengths of both architectures: the fine-tuned transformer and the MDX challenge winner. Results are cleaner but processing takes roughly 2× longer. Each model is loaded sequentially from the global model cache.

Export

Export Options & MIDI Extraction

VocalPro offers multiple export paths depending on your workflow — from simple vocal-only export to full multi-stem MIDI extraction.

1

Output Format

Choose from WAV (uncompressed, 44.1 kHz 32-bit float — highest quality), MP3 (compressed, adjustable bitrate default 320 kbps — smaller files), or FLAC (lossless compressed — best of both worlds). Format conversion is done via FFmpeg after the separation is complete.

2

Video Muxing

For video inputs, you have three output modes controlled by the video_output_mode setting:

  • both — Keeps the separated audio file AND creates a new MP4 with the clean vocals muxed back into the original video.
  • video_only — Only saves the muxed MP4 (with clean vocals). The standalone audio file is deleted after muxing.
  • audio_only — Only saves the separated audio files. No video muxing is performed.

Muxing uses FFmpeg with a filter chain: atrim=0:duration, apad to ensure sample-accurate sync with the video stream. If enabled, movflags +faststart optimizes the MP4 for web streaming.

3

Output Folder Structure

When a separation completes, the output folder (default output_vocals/) contains:

4

MIDI Extraction (Deep Dive)

The MIDI extraction feature converts melodic audio into playable MIDI files — useful for transcription, remixing, or feeding into a DAW. Here's the technical process:

  • Pitch Detection — Uses librosa.pyin (Probabilistic YIN algorithm) which estimates fundamental frequency (F0) using a probabilistic approach that handles noisy signals well. Frequency range: C2 (~65 Hz) to C7 (~2093 Hz).
  • Onset Detection — librosa.onset.onset_detect with backtracking identifies note boundaries from the spectral flux.
  • Note Quantization — For each onset-to-onset interval, the median pitch is computed from the F0 values within that segment. This pitch is converted to a MIDI note number using: midi_note = round(12 × log₂(freq / 440) + 69).
  • MIDI File Writing — A standard single-track MIDI file is written manually with proper header (MThd), tempo meta event (default 120 BPM), and Note On/Off events with delta-time encoding using variable-length quantity (VLQ).
  • Output Files — Each extracted stem produces: a raw .mid file (pitch quantized) and a debug .wav (the detected pitch contour as an audible sine wave for verification).
5

Comparison Samples

If enabled, VocalPro automatically extracts 3 random short clips (5 seconds each, from different regions of the file) and saves them as sample_N_music.wav (original) and sample_N_no_music.wav (separated vocals) in a samples/ subfolder. The file is divided into 3 equal regions, with one sample randomly selected from each region to ensure coverage across the full duration.

API Reference

Stem-Related API Endpoints

The backend exposes dedicated REST endpoints for stem mixing, previewing, and MIDI extraction. These are called by the Flutter frontend's Stem Mixer UI.

POST /api/stems/preview

Returns a 15-second WAV preview of stems mixed at given volumes. Accepts folder_name, volumes (per-stem gain map), and master_volume. Useful for auditioning slider adjustments before exporting.

POST /api/stems/export

Mix all stems at custom volumes and export as a single audio file (stem_mix.{format}). Accepts folder_name, volumes, master_volume, and output_format. Returns the output file path and size.

POST /api/stems/export_separate

Export each stem at its custom level as a separate file. Accepts folder_name, volumes, master_volume, and output_format. Returns a list of exported files with their sizes.

POST /api/stems/midi

Extract MIDI from a melodic stem file. Accepts file_path. Uses librosa.pyin for pitch detection, median-filtered note quantization, and standard MIDI file output (.mid). Returns the MIDI file path and note count.

📂 Output Folder Structure

All stem files are stored in output_vocals/{SongName}/. The GET /api/outputs/{folder_name}/stems endpoint lists all stem files in a given output folder by matching filenames against known stem suffixes (vocals, drums, bass, other, guitar, piano). The Flutter Results screen uses this to populate the Stem Mixer UI.
